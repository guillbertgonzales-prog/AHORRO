  3. Guarda los cambios y espera a que GitHub Pages publique la actualización.

Comprueba que esta dirección muestra una línea importScripts, y no un error:
https://guillbertgonzales-prog.github.io/AHORRO/OneSignalSDKWorker.js

No uses el HTML abierto con doble clic. Los avisos se activan en la página
HTTPS publicada. No es necesario subir el paquete del servidor a GitHub Pages.

PASO 2. AJUSTAR LA RUTA EN ONESIGNAL

En tu aplicación de OneSignal:
  Settings → Push & In-App → Web → Advanced Push Settings.
  Activa Customize service worker paths and filenames.

  Path to service worker files: /AHORRO/
  Service worker filename: OneSignalSDKWorker.js
  Si aparece updater filename: OneSignalSDKWorker.js
  Service worker registration scope: /AHORRO/

Conserva el tipo de integración Typical Site y el Site URL:
https://guillbertgonzales-prog.github.io

Guarda. Para que sea el botón de tu página el que pida el permiso, desactiva
los avisos de suscripción automáticos (auto prompt) y la campana flotante
si los activaste en OneSignal. También puedes desactivar su mensaje de
bienvenida para no confundirlo con una notificación de movimiento.

El App ID ya está colocado en el HTML:

PASO 3. REGISTRAR TU CELULAR

Abre en Chrome de tu Android:
https://guillbertgonzales-prog.github.io/AHORRO/

  1. Entra como siempre.
  2. Busca la sección Avisos en tu celular, cerca del final de la página.
  3. Pulsa Activar avisos y permite las notificaciones.
  4. Abre Datos de este celular y pulsa Copiar ID del celular.

Ese ID identifica la suscripción del celular, no es tu contraseña ni una API
key. Lo colocarás en la configuración del servidor en el paso siguiente.
Si añades otro celular, repite estos pasos y autoriza su ID también.
Si reinstalas Chrome o borras los datos del sitio, puede cambiar este ID.

PASO 4. PREPARAR EL REGISTRO PRIVADO EN APPWRITE

En tu proyecto de Appwrite abre Databases → alcancia-amor.
Crea una tabla nueva con:

  Nombre: Avisos enviados
  Table ID personalizado: avisos-enviados
  Columnas: ninguna
  Row security: activada
  Permissions: vacíos (sin lectura, creación, actualización ni borrado público)

No cambies la tabla de fotos. Esta tabla nueva guarda únicamente IDs para
recordar qué movimientos ya se notificaron. Solo la función del servidor
tendrá acceso por su clave temporal, con los permisos indicados más abajo.
No borres la tabla ni sus filas para evitar que se pierda ese registro.

PASO 5. CREAR LA FUNCIÓN DE ENVÍO

En Appwrite → Functions crea una función personalizada:

  Nombre: Avisos alcancía
  Runtime: Node.js 22 (o Node.js 20 si es el disponible)
  Entrypoint: src/main.js
  Build command: npm install --omit=dev
  Timeout: 120 segundos
  Execute access / permisos de ejecución: vacíos, sin Any ni Users
  API scopes de la clave dinámica: rows.read y rows.write únicamente

No necesita dominio público, webhook ni permisos de ejecución desde el HTML.
La consola de Appwrite permite al propietario probar la función, y el
programador de Appwrite la ejecutará después.

En Settings → Variables añade estas variables ANTES de publicar el despliegue:

  ONESIGNAL_API_KEY
    Crea una App API Key para esta aplicación en OneSignal → Settings →
    Keys & IDs. Pégala directamente aquí y márcala como secreta. NO la
    envíes por chat, NO la pongas en GitHub y NO uses la Organization API Key.

  PUSH_SUBSCRIPTION_IDS
    El ID de tu celular copiado en el paso 3. Para dos celulares, sus IDs
    separados por una coma. Solo se notifican estos destinatarios.

  JSONBIN_ACCESS_KEY
    La misma Access Key que utiliza actualmente tu alcancía para guardar
    en JSONBin (la variable JSONBIN_ACCESS_KEY del HTML original).
    Cópiala directamente a esta variable y márcala como secreta; no la
    envíes por chat. La función solo hace lecturas en JSONBin.

Estos valores públicos ya están como predeterminados en el código:
  JSONBIN_BIN_ID: 6adafd99ac6210605a4b0717
  PUSH_DATABASE_ID: 6adb7ca90026b0626e46
  PUSH_LEDGER_TABLE_ID: avisos-enviados

Appwrite proporciona automáticamente el endpoint, el Project ID y la clave
temporal de ejecución. No necesitas crear otra clave privada de Appwrite.

En Deployments crea un despliegue subiendo envio-automatico.tar.gz.
Actívalo cuando termine de compilar. El paquete contiene package.json y
src/main.js; no contiene claves privadas ni requiere dependencias externas.

PASO 6. INICIAR Y PROGRAMAR

Primero ejecuta manualmente la función una sola vez, desde Appwrite.
El resultado correcto inicial será status: baseline_created, sent: 0.
Esto registra el historial anterior para no enviar todos los movimientos
viejos. Si el resultado es error, corrige la configuración antes de continuar.

Después establece su programación cada minuto:
  Schedule / CRON: * * * * *

La frecuencia está sujeta a lo que permita tu cuenta de Appwrite. Revisa
sus límites de ejecuciones antes de dejarla programada.

PASO 7. PROBAR DE VERDAD

  1. Permite avisos de Chrome también en Ajustes de Android.
  2. Cierra la página en el celular que recibirá los avisos.
  3. Registra un depósito nuevo desde el otro dispositivo.
  4. Espera a que se guarde en JSONBin y se ejecute el siguiente chequeo.
  5. Debe llegar Nuevo depósito en la alcancía.
  6. Comprueba de la misma forma un retiro real que quieras registrar.

No hagas movimientos ficticios para probar datos financieros reales. Puedes
probar primero el canal con un mensaje de prueba en OneSignal, dirigido
únicamente a la suscripción de tu celular.

Los avisos pueden tardar alrededor de uno o dos minutos, más la demora del
sistema de entrega. Android puede retrasarlos por ahorro de batería,
restricciones a Chrome, falta de conexión o el modo No molestar. Salir de la
alcancía no desactiva la suscripción; usa Desactivar avisos para hacerlo.

Los avisos no muestran nombres, montos ni dedicatorias en la pantalla
bloqueada. Al tocarlos se abre la alcancía, que conserva su contraseña.
El servidor lee únicamente movimientos guardados. Editar montos o apariencia
no genera nuevos avisos. Si falla OneSignal se reintenta en la siguiente
ejecución; las peticiones incluyen una clave de deduplicación. Los movimientos
pendientes de más de 28 días se omiten para evitar reintentos demasiado antiguos.

SI ALGO FALLA

  • No llega ningún aviso: confirma que el ID autorizado es Subscription ID,
    no OneSignal ID ni App ID, y que OneSignal lo muestra suscrito.
  • El botón no se activa: revisa la ruta del worker y el dominio en OneSignal.
  • Se reciben pruebas pero no depósitos: falta el paso del servidor o la
    función está fallando. Revisa Executions en Appwrite.
  • MISSING_...: falta la variable indicada en el servidor.
  • REMOTE_HTTP_401/403: revisa las claves y los scopes de la función.
  • REMOTE_HTTP_404: revisa IDs, la tabla avisos-enviados y el Bin ID.
  • PUSH_NOT_ACCEPTED: revisa la suscripción autorizada y la App API Key.
